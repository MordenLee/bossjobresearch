# 候选人资料与问询

candidate.json 是跨站共享的真实履历与申请信息，存工作区而非安装目录。结构见 assets/candidate.template.json。

## 启动检查

新建求职任务先检查下表；续跑只检查变化项、未决问题和当前断点，不重复启动问卷。仅维护代码、查看进度、导出已有结果时无需索取简历和求职条件。

| 项目 | 启动时如何处理 |
| --- | --- |
| 简历/履历 | 个性化推荐需要可核实的简历或用户确认的履历。优先使用当前任务已确认的版本，记录文件名、版本日期或用户提供的资料来源；多版本冲突才询问。没有时请用户提供文件、路径或履历文本，不自行扫描个人目录。读取本地资料不等于允许向招聘网站上传。 |
| 岗位方向 | 使用用户明确的方向；用户要求从简历推导时，说明拟搜索的方向和依据。方向不明确且无法合理推导时集中询问，不将项目关键词自动变成必备岗位条件。 |
| 城市范围 | 明确包含/排除的城市或地区，允许用户明确选择全国、不限或远程。未填写不等于不限，也不沿用浏览器上次城市；城市未知时先问，暂不开展依赖地区的批量搜索。 |
| 薪资 | 可选；记录金额、币种、月薪/年薪、固定薪资/总包、区间上下限及跨区间是否接受。未知先留空，不硬过滤；有金额但口径不清时，在依赖该条件筛选前核实。 |
| 工作偏好与排除项 | 可选；行业、公司规模、雇主、岗位性质、远程/通勤、外包/派遣接受度等分别记录，区分硬条件与软偏好。未提及不自行添加限制。 |
| 网站与预算 | 使用指定网站；未指定时说明拟使用的已支持来源。采集批次、页数和时间/额度预算按当前任务规划，不写入通用偏好。 |
| 外部动作 | 找工作/推荐请求支持读取和审阅，不自动授权联系、发消息、上传、填写或提交。只询问用户当前确实要执行且缺少授权的动作；无投递授权不阻塞搜索推荐。已有范围明确的授权继续有效。 |

必要缺项一次集中询问，问题附带当前已知信息，例如：

> 已有资料：〈当前任务已确认的简历/方向〉。开始前还缺：〈简历来源、岗位方向或城市范围中的实际缺项〉。薪资和工作偏好可以一并补充，也可以暂留空。

不要将完整问卷逐项发给已有资料的用户。可选项不强制回答，不预先索取身份证、详细住址或与当前步骤无关的表单信息。仅要求收集 JD、且搜索范围已明确时可以先采集；履历不足的条目标记尚未匹配，不冒充个性化推荐。用户回复前继续不依赖缺项的资料整理或既有数据处理，不把等待超时当作回答。

将真实履历、偏好及授权分别写入任务的 candidate.json，将筛选规则及来源写入 review_policy.json。城市的包含/排除范围在策略中显式表达，不将候选人现居地自动用作搜索范围。必要问题保存在任务目录的 questions.json，并注明阻塞的步骤；不覆盖已有表单问题或已确认答案。

开始采集前展示一份简短的本轮摘要：简历版本/来源、岗位方向、城市范围、薪资口径、偏好与排除项、网站、采集预算及允许动作。摘要和未决项随 search-plan.json 保存在任务目录。事实来源、推导建议、未知项分开；信息充分时展示后直接继续，只有缺项或冲突才等待回复。调整条件时更新摘要和策略，并使受影响的旧审阅按现有版本校验失效；保留历史沟通和实际执行记录。

## 资料与授权字段

- cv：personal、education、experience、projects、skills、languages。沿用资料中的日期、任职类型、本人职责与协作贡献，不把参与经历扩大为独立负责的能力。
- evidence：JSON Pointer → `{source,quote,confirmed}`。转录用户 CV 的事实 confirmed=true，source 写文件路径，quote 写原文；推测不得作为申请事实。
- preferences：搜索方向、薪酬口径、平台、语言、城市及用户偏好的资料视图；目标与已有能力分开。主 Agent 将用于审阅的需求按来源编入独立 review_policy.json，v3 不在代码中另藏偏好门槛。两者冲突先核实并统一。

模板中的偏好值为空，不代表不限、否定或默认选择。地区、搜索语言、通勤评估、币种、薪酬周期及口径均从当前任务取得；缺失时保留未知。金额条件、排除名单和审阅倾向只进入任务 review_policy，不在通用校验器设置旁路规则。可选薪资解析工具只按显式传入的参数运行，其支持的格式不等于候选人偏好。
- answers：每条有 id、value、source、confirmed、scope。scope={site,job_key}，null 表示用户允许的通用范围，默认新答案限当前岗位。false/0 有效，null/空串缺失。
- documents：实际文件路径及出处，上传前核实正确版本。
- authorization：sources/actions/user_instruction 保存用户已允许的平台、动作与原话；可用 job_keys 限定岗位。contact/message/upload/fill/next/submit 分开。模板值和命令标志不能替代会话授权。授权变化不改变资格事实，但每次执行重新核验。

姓名、联系方式、入职日期、工作许可、搬迁、期望薪资等缺失时不猜测、不默认 Yes/No。筛选薪资门槛不等于表单期望薪资。CV 之间矛盾时问该事实。

questions.json 记录字段 id、标签、必填、问题、阻塞动作和 site/job_key；一次问当前必要信息，答复写入 candidate 后重新 prepare。不要提前索取所有潜在个人信息。

answer_ref 示例 `/cv/personal/email` 或 `/answers/0/value`。form.py prepare 仅使用 confirmed=true 的 evidence/answer，检查 scope。自由文本从真实 CV/JD 生成后也先保存有出处的 answer；不虚构经历。
